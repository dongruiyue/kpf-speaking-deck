# typography.md —— 排版规范（诊断 · 依据 · token · 落地）

> 起因：使用者反馈「每个页面都像一堆字 —— 没有字体/颜色/大小变化，符号数字乱用，
> 有的地方中文有的地方英文，可读性糟糕」。这份文件把问题量化、给出依据与 token，
> 之后所有外壳 / 模块 / 课时的排版**一律按这里改**，不再随手写 px。

## 一、诊断（2026-10-15 实测，改前基线）

| 项 | 实测 | 问题 |
|---|---|---|
| 字号 | `assets/shell.html` 里 **162 种** font-size 写法（15px×9、12px×9、clamp 各四五种…） | 没有阶梯，全是随手定值 |
| 字重 | **800×53 + 900×39 + 700×28**，而 400 只有 **1 处** | 所有东西都在喊 → 没有主次 → 「一堆字」 |
| 颜色 | **49 个十六进制色值** + 仅 16 个变量（`#fff` 18 次、`#7a5b10` 13 次…） | 没有语义色，改一处要翻遍全文 |
| 行高 | **9 种**取值（1.25 / 1.3 / 1.35 / 1.4 / 1.45 / 1.5 / 1.6 / 1.8） | 没有体系 |
| 字体栈 | 只有 3 处声明，正文写 `"PingFang SC","Microsoft YaHei",sans-serif` | 缺系统字体栈与西文/数字回退 |
| 中英混排 | 课时数据里 **约 600 条**标签同时含中英文，且顺序不统一（`Draw a question 抽题` / `Cover 盖住` / `Now: Team A · 答完补一句`） | 阅读时不断切换语言 |
| 符号 | `① ② ③`、`★`、`✓`、`▾`、`●`、`·`、`—`、`「」`、`（）` 混用，序号体系不统一 | 同一屏里两套编号 |

## 二、依据（规范来源）

| 来源 | 关键要求（本项目的落点） |
|---|---|
| **W3C《中文排版需求》clreq** <https://www.w3.org/TR/clreq/> | 汉字与西文字母/数字之间留**不多于四分之一个汉字宽**的间距（Web 上以**一个半角空格**近似）；标点遵循**行首/行尾禁则**；行内西文按西文规则处理 |
| **GB/T 15834—2011 标点符号用法** | 中文标点用全角（，。、；：「」《》），西文与数字用半角；书名用《》，引语用「」 |
| **GB/T 15835—2011 出版物上数字用法** | 数量、编号用阿拉伯数字；序数词（第一、二）用汉字；**同一层级序号格式统一** |
| **模块化字号阶梯**（常用比例 1.25） | 字号由基准 × 比例生成，而不是逐个拍；<https://blakecrosley.com/blog/typography-systems> |
| **字重只用三档** | 正文 400 / 强调与标签 500–600 / 标题才用重字重；不要满屏 700+ <https://www.glammer.ai/blog/ui-typography-type-scale-that-works> |
| **WCAG 2.2 AA** | 正文对比度 ≥ 4.5:1、大字号 ≥ 3:1；正文行高 ≥ 1.5；行宽建议 60–75 个西文字符（中文约 35–45 字） |

## 三、Token（外壳 `:root` 里定义，全项目只许用这些）

### 3.1 字号阶梯（比例 1.25，基准 16px）

| token | 值 | 用途 |
|---|---|---|
| `--fs-2xs` | 12px | 脚注、页码、极小的辅助标记 |
| `--fs-xs` | 13px | 次要说明、徽标 |
| `--fs-sm` | 14px | 教师控制台正文、辅助行 |
| `--fs-base` | 16px | **正文基准**（教师端默认） |
| `--fs-md` | 20px | 小标题、卡片标题 |
| `--fs-lg` | 25px | 节标题 |
| `--fs-xl` | 31px | 页面标题 |
| `--fs-2xl` | 39px | 学生屏大标题 |
| `--fs-3xl` | 49px | 学生屏题目（配合 clamp 下探到 32px 保底） |

投影端（`body.audience`）用同一套 token 的**投影档**：正文 ≥24px、题目 ≥32px（写进 clamp 下限），
不另起一套字号。

### 3.2 字重（只三档 + 一个例外）

| token | 值 | 用途 |
|---|---|---|
| `--fw-body` | 400 | 所有正文 |
| `--fw-medium` | 500 | 标签、次级强调 |
| `--fw-semibold` | 600 | 标题、按键 |
| `--fw-bold` | 700 | **仅**计分数字、倒计时等需要一眼看到的极少数位置 |

> 800 / 900 **全面停用**。当前 92 处 800/900 是「一堆字」的主因。

### 3.3 颜色（语义 token，只增不改）

| token | 浅色 | 用途 |
|---|---|---|
| `--c-bg` | `#FAF9F5` | 页面底色（暖白） |
| `--c-surface` | `#FFFFFF` | 卡片/面板 |
| `--c-surface-soft` | `#EAF2E6` | 辅助任务区（**浅绿只用于此**） |
| `--c-line` | `#E1DED4` | 分隔线（1px 实线，禁虚线） |
| `--c-ink` | `#23282B` | 正文 |
| `--c-ink-2` | `#5C6469` | 次要文字 |
| `--c-ink-3` | `#8A9095` | 极次要（页码、占位） |
| `--c-accent` | `#21644E` | 主强调（深绿）：标题、主按钮、选中态 |
| `--c-team-a` | `#21644E` | A 队 |
| `--c-team-b` | `#B4472C` | B 队 |
| `--c-warn` | `#B8902A` | 时间/提醒（**琥珀只表达时间与提醒，不做装饰底色**） |

- 琥珀/黄色**不再做整块底色**（现在的黄条 + 黄卡是「乱」的来源）；需要强调用 `--c-surface-soft` 或加粗。
- 虚线框**停用**，一律 1px 实线。

### 3.4 行高与间距

| token | 值 | 用途 |
|---|---|---|
| `--lh-display` | 1.2 | 大标题、学生屏题目 |
| `--lh-ui` | 1.5 | 按钮、标签、单行控件 |
| `--lh-body` | 1.7 | **中文正文**（clreq 建议 1.5–1.8） |
| `--sp-1..6` | 4 / 8 / 12 / 16 / 24 / 32px | 间距一律取自这六档 |

### 3.5 字体栈

```css
--font-sans: -apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB",
             "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif;
--font-serif: Georgia, "Songti SC", "Times New Roman", serif;   /* 仅 PF 主题的展示标题 */
--font-num: ui-monospace, SFMono-Regular, "SF Mono", Menlo, monospace;  /* 计时、分数 */
```
- 西文与数字**不单独换字体**，靠系统回退即可；但计时/比分加 `font-variant-numeric: tabular-nums`。

## 四、中英混排与标点规则（本项目约定，逐条可查）

1. **同一控件内语言顺序固定**，不许一处英文在前一处中文在前：
   - **教师操作**（按钮、控制台、教学提示）→ **中文为主**，英文只在必要时以括号补充：
     `抽题`、`盖住`、`换手`、`重来`；**不写** `Draw a question 抽题`。
   - **学生任务**（题干、句架、范文、功能语言）→ **英文为主**（那是目标语言），
     中文提示放**下一行小字**（`--fs-sm` + `--c-ink-2`），不与英文同行。
2. **中英之间一个半角空格**（clreq 四分之一字宽的 Web 近似）；不要连用两个空格，不要用全角空格。
3. **标点**：中文用全角（，。、：；「」《》），英文与数字用半角；中文文本里禁止出现英文逗号 `,` 与英文引号
   （`"` 只用于代码/英文原文内部）。
4. **序号只用一套**：`1. 2. 3.`（阿拉伯数字 + 半角点 + 空格）。停用 `① ② ③`、`★`、`●` 混排；
   勾选态统一用 `✓`，展开态统一用 `▾`。
5. **数字**：数量/编号/分数/时间用半角阿拉伯数字（GB/T 15835）；「第一、二」这类序数词用汉字。
6. **行宽**：正文容器 `max-width` 控制在 60–75 西文字符（中文约 35–45 字）以内，超长行要拆栏或缩宽。
7. **一屏一条主信息**：投影页每页只放一块主内容（已有的「一页一件事」原则），
   排版上体现为「标题 600 + 正文 400」的对比，而不是全部加粗。

## 五、落地清单（谁要改）

| 位置 | 改什么 |
|---|---|
| `assets/shell.html` `:root` | 加 token（三节 3.1–3.5），**删掉** 162 处零散字号 / 120 处 800·900 / 49 个裸色值的写法，全部换 token |
| `assets/shell.html` 组件 CSS | 黄底、虚线、重阴影一律去掉；`.q-bar`（题目）在观众屏用 `--fs-3xl` + `--fw-semibold`；辅助文字降到 `--fs-sm` + `--fs-ink-2` |

## 六、验收

1. **数值**：`grep` 复查——外壳里 800/900 应为 **0**；裸十六进制色值应为 **0**（除 token 定义处）；
   字号写法应只剩 token 引用（允许 clamp 的投影档）。
2. **脚本**：`verify.py` 12 条仍全过（改版不能动功能与计分）。
3. **观感**：三档视口（1280×720 / 1366×768 / 1920×1080）× 教师端/学生屏截图对照
   —— 判据是「一屏一眼看出主次」，不是「数字达标」。
4. **回归**：九份产物全部重建 + `check-classes` 未定义 0 + FCE 12 视图自然高度偏差仍 ≤2%
   （排版改动会改高度，属授权改版，需在 `verify.py` 的 `AUTH_DEV` 里逐条登记，不许假装 0.00%）。

## 七、布局规范（投影屏/教室屏）——依据 C.R.A.P. 与网格系统

> 起因：2026-10-15 用户两次否定 —— 先是「整块挤在左上角」，我把内容改成全部居中后又被否定
> 「这看起来不更难看吗」。根因不是"居中还是左上"，而是**没有统一的对齐轴**：
> 当时屏上是「标题左上 + 题目居中 + 卡片整宽居中」三套对齐并存。
> 用下面的标准重排后通过。

### 7.1 四条判据（Robin Williams《The Non-Designer's Design Book》的 C.R.A.P.）

| 原则 | 在本项目里的硬性要求 |
|---|---|
| **Alignment 对齐** | 一屏**只用一条对齐轴**。所有元素（页面标签、题目、次要信息、支撑卡）共用同一条左基线。**禁止自动居中** —— Williams 原文：*avoid automatic centering*。 |
| **Proximity 邻近** | 相关的靠紧、不相关的拉开：同一组内用 `--sp-3/4`，组与组之间用 `--sp-6`（32px）。禁止"处处等距"。 |
| **Contrast 对比** | 要么明显不同、要么完全一样。相邻层级字号比 **≥ 2:1**（本项目：题目 49 / 关键词 20 / 标签 13）。禁止 25 vs 31 这种"看起来差不多又不一样"的糊状尺寸。 |
| **Repetition 重复** | 所有屏共用同一网格与同一套字号角色；同类元素在每屏都长一样。 |

参考：[C.R.A.P. Principles (UW–Madison DesignLab)](https://designlab.wisc.edu/resources/design-tips-and-tricks/crap-principles/)

### 7.2 网格（Nancy Duarte《slide:ology》：把元素放进网格，它们才不会像随手摆的）

- **外边距**：左右各 **6.4%**（1920 下 = 122px）；上下留白由垂直居中分配。
- **内容列**：`max-width: 1280px`，左对齐；支撑卡与内容列同宽。
- **间距栅格**：一律取自 `--sp-1…6`（4/8/12/16/24/32px，8pt 栅格）。
- **垂直构图**：整块在视口内垂直居中（`main` 用 flex + `justify-content:center`），
  但**块内一律左对齐** —— 居中只作用于"块在屏上的位置"，不作用于"块内文字"。

### 7.3 投影可读性（课堂材料通行要求）

- 标题与章节标题必须有**明显不同**的字号（不是 5px 之差）。
- 一屏一个主信息（Presentation Zen 的 one idea per slide）：本项目的「一页一件事」在版式上
  体现为**只有一个元素处于 Display 角色**，其余 ≤ 它的 45%。
- 每屏要点数 ≤ 5 条（本项目的支撑卡正好 3 条）。

### 7.4 学生屏的落地版式（照此实现，勿再即兴）

```
┌ 1920×1080 ─────────────────────────────────────────────┐
│  ← 6.4% →                                                │
│  4. 抽题速答         ← 13px、--c-ink-2（组 A：页面标签）  │
│                                                          │
│  KET SPEAKING PART 1 ← 13px、--c-ink-2                   │
│  点「抽题」抽一道考官问题  ← 49px、semibold（组 B：唯一焦点）│
│  轮到 Team A          ← 20px、--c-ink-2                   │
│                                                          │
│  ┌─ 支撑卡（max-width 1280，左对齐，浅绿 --c-surface-soft）┐│
│  │ 1. also      再说一点   ← 20px semibold + 14px 注解   ││
│  │ 2. because   说原因                                   ││
│  │ 3. for example 举个例子                               ││
│  └──────────────────────────────────────────────────────┘│
└──────────────────────────────────────────────────────────┘
```

- 组 A 与组 B 之间 `--sp-6`（32px）；组 B 与支撑卡之间 `--sp-6`。
- 支撑卡内每行是一个 `.st-row`：关键词 `--fs-lg`(20) + 中文注解 `--fs-sm`(14) + 计数 `1. 2. 3.`。
- **不出现**：圆形徽标（只在首行出现会破坏对齐）、第三层语言（中文后的纯英文括号，已全线清除 254 处）。

## 八、练习页版式契约（`modules/*.js` 一律照此办）

> 起因：2026-10-15 用户第三次否定 —— 「按钮歪七扭八，中间字体又黑又粗，按钮不对齐，左边一个右边一个」
> 「地狱级排版」，点名 KET U7L3 模拟考试页与 PET L4 Part 4 练习页。根因两条：
> ① **`.stage` 到教师端还是 `text-align:center` + `align-items:center`**（§七 只改了学生屏），
> 于是一屏里「环节 Tab 居中 / 按钮在左 / 计分居中 / 说明在左」四套对齐并存；
> ② **正文类元素被当成题目做**（discussion 的范文 `--fs-3xl` 半粗 → 整屏最黑最粗的字是范文，题目反而小）。
> 三条契约：**一条左轴 · 四组纵向顺序 · 字号角色不许越级**。

### 8.1 一条左轴

- 舞台（`.stage`）内**所有直接子元素**都是 `width:100%`、左对齐、共用同一条左边缘；
  **禁止**任何 `justify-content:center` / `text-align:center` / `margin:auto`
  （页面级的「返回」「下一环节」导航按钮除外）。
- 唯一的分寸：`justify-content:center` 只允许出现在 **flex 列方向**（= 把整块摆在盒子中间，§7.2），
  它作用于「块的位置」而非「块内的文字」；**水平**居中一律禁止。
- 落地：外壳 `.stage{align-items:flex-start;text-align:left}` + `.stage > *{width:100%;text-align:left}`；
  模块里成组的元素套 `.prac-set`（`width:100%`、`align-items:flex-start`）。
- **卡片内部不算页面对齐**：`.flash-card` / `.bingo-cell` / `.pair-slot` 里的图文是格子自己的视觉单元，
  允许内部居中；契约管的是**页面上排队的元素**。
- **页面级家具**：外壳底栏 `.next-row`（左轴上的撤销 / 右端的下一环节）与讲义框 `.deck-foot` 的翻页
  不受四组顺序约束（它们是「页面」的一部分，不是练习内容）。

### 8.2 四组纵向顺序（组间 `--sp-6`，组内 `--sp-2/3`）

| # | 组 | 谁在里面 |
|---|---|---|
| 1 | 内容 | 题目 `.question`（`.dq-text` / `.q-bar` 同档）+ 次要信息 `.big-word` / `.dq-meta` / `.turn-label` |
| 2 | 素材 / 选项 | 图片、选项卡、支撑卡：`.photo-pair` / `.task-row` / `.chip` / `.stepcard` / `.flash-grid` / `.sentence`（范文） |
| 3 | 教学控件 | **一行**按钮（`.btn-row`）—— 抽题 / 揭晓 / 计时 / 换手 / 重来 **全在这一行** |
| 4 | 计分与说明 | **一行** `.score-team` + 说明 `.rule-line` / `.big-sub`（计分在前、说明在后） |

- 组间 32px、组内 8–12px：`.stage{gap:var(--sp-6)}`，同组元素套 `.prac-set`（`gap:var(--sp-2)`）。
- 组缺就不写（没有题目就不留空组）；**组序不许换**。
- 例外一：自带分页的模块（`tool-pager` 句型库、`teach-deck` 讲义）的「上一页 / 下一页」是页面级导航，
  允许常驻内容上方（`references/shell-boundary.md` 的既定设计），但同样必须 `justify-content:flex-start` 落在左轴上。
- 例外二：**选题条**（`photo-pair-steps` 的 `.task-row`）——课时的空态文案写死「先在上面选一套真题」，
  文案不许改，所以选题条留在内容上方（同样一行、同样左轴）。

### 8.3 字号角色（谁都不许越级）

| 角色 | 类 | 规格 |
|---|---|---|
| 题目 | `.question` / `.dq-text` / `.q-bar` | display：教师端 `clamp(--fs-lg, 2.2vw, --fs-2xl)`；投影 clamp 到 `--fs-proj-q`；`--fw-semibold` |
| 答案 / 范文 | `.sentence` | **阅读级**：`--fs-lg` + `--fw-body`（正文不许用 display 字号） |
| 次要信息 | `.big-word` / `.turn-label` / `.name-scroll` | ≤ `--fs-md`（投影另按 §7.4）、`--fw-medium`、`--c-ink-2` |
| 标签 / 说明 | `.dq-meta` / `.rule-line` / `.big-sub` / `.flash-ops-label` | `--fs-sm` + `--c-ink-2` |

- **禁止**给正文用 display 字号或 700+ 字重；800 / 900 全面停用（§三.2）。
- 一屏只有一个元素处于 display 角色（§7.3）。**成段的题干 / 考官原话是正文**（`.scaffold`），
  一律阅读级 —— 只有一行读得完的题目才配 display。

### 8.4 按钮不许散

- 同一类动作**必须在同一行**；只有页面级导航（返回 / 下一环节）可以在两端。
- 一个练习页的教师控件只有一行 `.btn-row`；计分是另一行 `.score-team`（两者分开不算「散」）。
- 不许「上面一行按钮 + 下面又一行按钮」：`draw-question` 的「抽题」与「换手 / 重来」、
  `mock-exam` 的「突袭」与「互评表」，都必须并进同一行。

### 8.5 句架条（`#frameBar`）不许重复页面内容

页面里**已经显示**同类句架时，底栏必须整条隐藏（`display:none`），不是只清空内容
（开关按钮是 teacher-only，观众屏那条框会剩一个空壳）。

- 声明方式：课时 `LESSON_META.frameBar.suppress = [环节 id…]`（缺省常驻底栏，行为不变）。
- 已声明：`fce-l5-part3 ["t1","t2"]`、`fce-part1-2 ["p2"]`、`pet-l4 ["p2","p3"]`、
  `pet-l6 ["p2"]`、`pet-u2l3 ["task"]`、`sample-pet ["p2","p3"]`、`ket-u8l3 ["draw"]`。
- 判据是**逐字重合**：`negotiate` / `photo-relay` / `photo-pair-steps` 的 `.chip` / `stepRow` 句架
  与底栏是同几句话 → 必须 suppress；`tool-pager` / `mock-exam` / `discussion` 的页面句架与底栏不同
  → **不许** suppress（suppress 了学生就看不到那几句）。
- 条内文字走**同一条左轴**（`justify-content:flex-start`），水平居中一律禁止 ——
  「页面对齐了、底栏还居中」等于又留一套对齐。

## 九、讲义页版式契约（`STEPS[].lesson` 的 blocks）

> 起因：2026-10-16 用户第四次否定 —— 「怎么读？可读性在哪里？你能最简单的分 bullet point 也可以啊」，
> 点名 FCE L5 第 1 页「Part 3 是什么 · 填空」：8 句长句按 `.dk-i`（25px、满宽、`--lh-display`）
> 连排成一段，学生读不出结构。

### 9.1 成段的说明文字一律分点，不许连排成墙

- 一页里 **≥3 句**叙述性文字（讲义 `text` 块的 `i` / `ae` / `ai` 行）→ 必须改成列表。
  用 `html` 块 + `<ul class="dk-ul">`：一条一句，项目符号用 accent，`b`（空格 / 关键词）用 accent。
- 条数多时按语义分组，每组一个小标题 `<div class="dk-h">① …</div>`（3 组以内）。
- 一页只能扛这么多：**自然高 ≤1100px**（`verify.py` 第 5 条）。超了就拆页，
  不许靠缩放掩盖（外壳自己在 z<0.9 时会 `console.warn('这一屏内容过密…')`）。

### 9.2 对话原稿用 `.dk-dlg`，不用 `.dk-ul`

- 台词逐轮成行、说话人挂起缩进（`padding-left:6em;text-indent:-6em`），`list-style:none`
  —— 戏剧脚本本来就有结构，不要再套一层项目符号。
- 原稿超过 ~10 轮就拆页（`听力原稿 1/2`、`2/2`）。

### 9.3 讲义列表的行高取 `--lh-ui`（1.5），不取 `--lh-body`（1.7）

`--lh-body` 是中文长段落的规格；讲义列表靠分隔与缩进分块，1.5 既省高度也够读
（1100px 的硬判据就是被这一条卡住的）。字号仍走角色表：列表 `.dk-ul`/`.dk-dlg` = `--fs-base`，
投影端统一 `clamp(--fs-proj-body,1.6vw,--fs-xl)`。

## 十、挖空练习契约（`modules/gap-fill.js`）

> 起因：2026-10-16 用户第五条 —— 「听力音频在下一个『2. 练习』的按钮下面，我得打开后面再点开前面」
> 「就不能做到点一下出一个答案吗？空必须都填好吗？实现不了挖空练习啊」。

### 10.1 两条硬规则

- **答案不许写进讲义**。填空 / 归类一律放 `gap-fill` 模块（练习视图），题干里不许用 `<b>` 印答案。
- **答案不许进 DOM**。只有揭晓时才把答案文字写进按钮 —— 否则观众屏源码里就躺着答案，挖空等于没挖。
  所以按钮初始是空的（`data-on="0"`，CSS 给一枚 `?`），揭晓才 `textContent = 答案`。

### 10.2 一屏五组（§八 的顺序）

① 题目 + 说明（`.question` / `.scaffold`）→ ② 录音（可选，借 `audio-player` 实例）
→ ③ 句子列表（`.gf-list`，一句一行，空是 `.gf-blank` 按钮）→ ④ 一行控件
（揭晓下一空 / 全部揭晓 / 揭晓归类 / 重来）→ ⑤ 说明 `.rule-line`。

- **录音必须和题在同一屏**：借 `TK.modules['audio-player']` 的实例挂进 `.prac-set`，
  不许让老师为了放音切视图（见 `pitfalls.md` 第十一轮）。
- `head`：分组小标题（`.gf-head`，accent 色）；`cat`：归类标签，**单独一层**揭晓（先填对词，再归类）。
- **词库**（可选 `bank`）用 `.reminder-chips` 渲染，**不许做成按钮** —— 它不是可点的选项。
- 「揭晓下一空」按显示顺序走，按钮上带 `（还剩 N 空）`，老师知道进度。
