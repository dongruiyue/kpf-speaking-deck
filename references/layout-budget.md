## 一、测量口径（先统一，否则数字互相打架）

| 项 | 口径 |
|---|---|
| 视口 | headless Chrome `--window-size=1920,1080`，但**探针自报的视口是 1920×993**（窗口外框比视口高 87px）。所以「白空」的分母是 **993**；而 §七 #3 的判据是跟 **1080** 比的（1080 = 演讲者模式的标称屏高）。这两个数**不能混用**。 |
| 带 zoom 的 `bottom` | `main.getBoundingClientRect().bottom`，在**翻到这一屏**的时候量 → 判「有没有冲出屏幕」（#3 用的就是它）。 |
| 自然高度 | 清掉 `header` / `.steps` / `main` 与 `documentElement` 的 zoom 之后再量 `bottom` → 与缩放无关的**版式真值**，判「外壳承不承载得住」（#12 用的就是它）。 |
| 量法 | `scripts/probe.js`（只读探针）→ `scripts/validate-deck.mjs`（M1/M2 + 原始值 `--raw`）／`scripts/verify.py`（12 条判据 + 对照表）。 |

**缩放是怎么来的**（决定「自然字号 → 投影字号」的换算）：

- 观众屏（外壳 `fitAudience`）：清 zoom 量最差屏 → `z = min(1, (vh − 8) / naturalH)`，下限 **0.55** →
  再**自校正最多 3 轮**（直接量 `main.bottom`，还溢出就按比例再缩）；非强制刷新时**只降不升**。
  宽度永远铺满（`body.audience main{padding:6px clamp(20px,2.2vw,72px) 80px;max-width:none;width:100%}`）。
- 教师端（外壳 `computeFitZoom` / `setZoom`）：`sessionMinZoom` **只降不升**（避免按钮忽大忽小），
  zoom 加在 `header` / `.steps` / `main` 上，**控制台不受影响**；`measureWorstScreenH` 会**逐页**
  把讲义每一页量一遍（只量当前页会漏掉最高的那页，实测漏过 1264px 与 762px 的差）。

## 二、逐条预算

### 1) 讲义每页自然高 ≤ 1100px

- **判据**：观众屏每一页讲义的自然高 ≤ 1100px（2026-09-30 由 ≤900px 调整，依据与拍板见 `pitfalls.md` C6）。
- **出处**：`shell-boundary.md` §七 #5。
- **怎么量**：探针 `decks`（清 zoom、逐页强制 `.on` 后量 `getBoundingClientRect().height`，四舍五入取整）。
- **现状**：**✅ 8 页全部 ≤1100**（最大 1096 = `overview:2`，迁移前就是这个值，见 §四留痕）。

### 2) FCE 投影正文实际字号 ≥ 20px

- **判据**：≥ 20px（2026-09-30 由 ≥22px 调整，依据与拍板见 `pitfalls.md` C6）。
  **注意它不是一个常数** —— 它是「**讲义正文自然字号 × 该场缩放**」，
  而缩放随视口（和自校正轮次）变，所以**必须连同视口一起报**。
- **出处**：`shell-boundary.md` §七 #5。
- **怎么量**：探针 `decks` 逐页取正文候选块（`.dk-i / .dk-mA / .dk-do / .deck-tips-list li / .deck-kv / .deck-time span / .deck-steps .dk-do …`）
  的 `getComputedStyle().fontSize` **最大值**（此时已清 zoom，得到的是**自然字号**），
  再乘该场缩放（探针 `vz`）。
- **现状（视口 1920×993）**：自然字号 32.64–40px，该场缩放 **0.63** → 投影上最小正文
  **32.64 × 0.63 ≈ 20.6px ≥ 20px**，**达标**（旧判据 22px 下差 1.4px 的留痕见 §四）。
- **口径警告**：同一份产物换视口（例如 Safari 1710 宽、或自校正多跑一轮）缩放会变，这个 20.6 会跟着变；
  引用这个数字时必须写「视口 1920×993、缩放 0.63」。

### 3) 每个视图 `main.bottom ≤ 1080`

- **判据**：1920×1080 演讲者模式 + 观众屏，**每个视图**（环节 × 讲/练 × 讲义每页）带 zoom 的 `main.bottom ≤ 1080`。
- **出处**：`shell-boundary.md` §七 #3。
- **怎么量**：`node scripts/validate-deck.mjs <课时>` 的 M1 表（Δ vs 1080 一列）；
  或 `python3 scripts/verify.py <课时>`。
- **现状**：**✅ 三份全部达标**（视口 1920×993，2026-09-30 复测）：

  | 产物 | 教师端最大 bottom | 观众屏最大 bottom | 视图数 |
  |---|---|---|---|
  | FCE | 917.16（`p2|teach|3`） | 894.44（`overview||2`） | 12 |
  | PET | 978.66 | 968.58 | 22 |
  | KET | 986.30 | 962.66 | 7 |

  余量最小的那一屏是 PET 观众屏（968.58 / 993 = 97.5%），也就是**最紧的一屏只剩约 24px**。

### 4) 观众屏 `left = 0`、右侧不留白

- **判据**：观众屏每个视图 `left = 0`，且**右边不留白**。
- **出处**：`shell-boundary.md` §七 #4；读法见 `pitfalls.md` C4。
- **怎么量**：探针 `vlr`（每个视图的 `main.getBoundingClientRect()` 的 left / right）；`verify.py` 报第 4 条。
- **口径（重要）**：实测每个视图是 `left = 0`、`right = 1920`（= 视口宽），**右边距 = 1920 − 1920 = 0**。
  按「左右都铺满」判就是达标；若按字面 `right === 0` 判则**永远不可能**（那是把 left/right 记混了）。
- **怎么实现的**：观众屏把 `main` 设成 `max-width:none;width:100%`，所以缩放多少都铺满整屏（同一套几何）。

### 5) 照片 `naturalWidth > 0`；投影上照片不能太小

- **判据 A（硬）**：DOM 里所有照片 `naturalWidth > 0`（**素材没丢**）。
- **出处**：`shell-boundary.md` §七 #6。
- **怎么量**：探针 `img`（`naturalWidth` 为 0 的张数）/ `imgAll`；`--raw` 会一起打出来。
- **现状**：**✅** FCE `n=2 / bad=0`、PET `n=2 / bad=0`、KET `n=29 / bad=0`。
  （`n` 是**当下 DOM 里的张数**：FCE/PET 一次只显示一套题的两张；素材目录里分别是 8 张 / 3 张 / 6 张。）
- **判据 B（软，只有口径没有闸）**：投影上照片要**大**。出处是 golden FCE 自己的 CSS 注释：
  `/* 照片是这个环节的核心素材：投影上必须够大（1920 下 ×缩放 ≥420px） */`，
  实现是 `body.audience .photo-pair.sm .ph{max-width:min(640px,34vw)}`（1920 下 = 640px）。
  **这次没有实测每张照片的显示宽度**（探针只统计 `naturalWidth`）→ 要量就在页内量
  `.photo-pair img` 的 `getBoundingClientRect().width`；**目前属未核实**。

### 6) 一页只放一块内容

- **判据**：讲义一页只讲一件事；一页里不堆多块互不相干的内容。
- **出处**：用户当初的原始要求 + 外壳里的注释原话
  `一页只放一块内容，字号大、行距松，投影上一眼看完`（`assets/shell.html` 的讲义分页段）+
  golden FCE 的教学提示文案「讲解现在是**分页讲义**……**一页只讲一件事、字号大**」。- **怎么量**：半人工——看 `lessons/<课时>.js` 里每个 `lesson[]` 页的 `blocks[]` 是否只有一块主线内容
  （操作卡 / 一组句架 / 一段范文 / 一组时间轴），再看 M2 标题间距与页自然高有没有反常。
- **现状**：FCE 8 页、PET 16 页，都是一页一块（页高 604–1096px，见 `decks`）。

### 7) 观众屏字号放大与自适应

- **判据**：同一份文件在观众屏上字号要**更大**（投影上看清），且**自动落进窗口**（不出现滚动条）。
- **出处**：`shell-boundary.md` §二「观众屏适配 `scheduleAudFit` / `audUsed` / `fitAudience`」+
  外壳 CSS 里那一排 `body.audience …clamp(…)` 规则（讲义标题 / 块标题 / 要点列表 / 时间轴各一档）
  + 课时级覆盖 `lessons/<name>.css`（PET / KET 自己的取值）。
- **怎么量**：探针 `decks` 的 `px`（自然字号）在 `T` 与 `A` 两个角色下对比；M1 看有没有溢出。
- **现状**：FCE 观众屏讲义正文自然字号 **32.64–40px**（教师端同页 21–36px）；
  PET 观众屏 **24–27.84px**。自校正后的缩放：FCE 0.63、PET 0.72–0.75、KET 0.99。
- **注意**：探针的字号候选清单是按外壳的讲义块类名写的（`.dk-*` / `.deck-*` 等），
  **PET 用 `{type:'html'}` 整块承接旧版讲义**的页（`intro:1/2/4`）量出来是 `0` —— 那一列对它们不适用，
  不是「字号为 0」。

### 8) 第 12 条：与迁移前逐视图自然高度偏差 ≤ 2%

- **判据**：与**迁移前**（`golden/`）的同名视图对比**自然高度**，偏差 ≤2%，逐视图列表报出。
- **出处**：`shell-boundary.md` §七 #12。
- **怎么量**：探针 `nat`（清 zoom 后的 `main.bottom`）；`python3 scripts/verify.py <课时>` 出对照表。
- **为什么必须用自然高度**（§七 的原话，照搬）：
  > 带 zoom 的 `bottom` 受「**整场缩放只降不升**」影响 —— 同一个文件、同一探针，两次运行的数值会差
  > **10–95px**（实测过：`p2/2` 一次 999.32、一次 1094.32）。**自然高度与缩放无关，是版式真值**，
  > 只有它能判「外壳是否承载住了」。
- **现状**：FCE 已 12/12 逐视图一致（偏差 0.00%）；PET / KET 按 `pitfalls.md` C2 的口径**只报事实**（讲解从一屏三栏变成翻页讲义是既定升级）。

### 9) KET 播放器：教师端 1 个、观众屏 0 个

- **判据**：教师端 `<audio>` 1 个（带播放器盒子）；观众屏 **`<audio>` 都不建**、也没有播放器盒子。
- **出处**：`shell-boundary.md` §五 铁律 4、`SKILL.md` 铁律 8、`pitfalls.md` §八（播放器三条老规矩）。
- **怎么量**：探针 `audio`（`{els, box}`）；`verify.py` 会打成一行。
- **现状**：**✅** 教师端 `els=1 / box=true`；观众屏 `els=0 / box=false`。

### 10) M2 标题间距：讲义页标题 ↔ 首个内容块 = 4–24px

- **判据**：`validate-deck.mjs` 的 M2 —— 讲义页标题（`.deck-title`）底边到该页首个内容块顶边
  的距离落在 **4–24px** 里；超出算异常（负值 = 压在一起，偏大 = 页面顶部发飘）。
- **出处**：这张「正常带」不是规格里写的，是从外壳 CSS 推出来的（写在这里以便判断）：
  `body.audience .deck-top{padding-bottom:5px;}`／默认 `.deck-top{padding-bottom:8px;}`
  再加上首块自己的 `margin-top`（`.dk-h` 是 9px；`.deck-page` 里多数块 0–14px）。
- **怎么量**：`node scripts/validate-deck.mjs <课时>`（清 zoom 后逐页强制显示再量，与探针量讲义页高同一个手法）。
- **现状**：**✅ 异常 0 页**。FCE 8 页：教师端全是 **19.00px**、观众屏全是 **16.00px**
  —— 两者差 3px 正好等于上面那两组 `padding-bottom` 的差，说明这条量法对得上 CSS，
  量到的值也是「间距」而不是别的盒子在作怪。

## 四、规格写了、但实际**没达到**的项（不许当回归修）

> **状态更新（2026-09-30）**：这张表的两项都**已按「改规格」结案**（用户拍板，见 `pitfalls.md` C6），
> 表保留作留痕 —— 下次再遇到「规格与实测对不上」，仍走本节末尾的处理流程。

这些项目**规格与真实实现对不上**，而且**迁移前就是这样**。规矩是：先证明「不是回归」，
再决定「改规格」还是「单独记一笔」——**绝不允许为了让判据好看去压字号/删内容**。

| 项 | 规格 | 实际（视口 1920×993） | 是不是回归 | 处理 |
|---|---|---|---|---|
| 讲义每页自然高 | ≤ 900px（§七 #5，旧值） | FCE 8 页里 **3 页 > 900**，最大 **1096px** = `overview` 第 2 页；逐页 997 / **1096** / 763 / 837 / 900 / 690 / 950 / 853 | **不是**。`overview:2` **迁移前就是 1096px**（`pitfalls.md` C3 记的历史读数 1102，同一页不同口径），golden 与重建一致 | **已处理（2026-09-30，用户拍板）**：判据已调整为 **≤1100px**（三份工具实测最大 1096.45；1100 是 1080 视口下不滚动的经验上限），见 `pitfalls.md` C6；本行保留作留痕 |
| FCE 投影正文字号 | ≥ 22px（§七 #5，旧值） | **20.6px**（32.64 × 0.63 缩放） | **不是**。上一轮 `pitfalls.md` C3 量到的缩放是 0.69 → 22.5px（勉强达标）；0.63 是观众屏自校正后的结果，两者都是实测，差别来自缩放/视口 | **已处理（2026-09-30，用户拍板）**：判据已调整为 **≥20px**（自然字号 32.64 × 最低缩放 0.63 = 20.6px；引用时必须带视口与缩放），见 `pitfalls.md` C6；本行保留作留痕 |

**这类项目的处理流程（写死在这里，下次照做）**：

1. **先判定是不是回归**：拿 `golden/` 的同名视图比**自然高度**（第 12 条）。一致 → 既有状况，**不许记成回归**。
   这一步用的是 `python3 scripts/verify.py <课时>` 的对照表。
2. **既有状况只有两条出路**：
   - **改规格**：改 `shell-boundary.md` §七 的判据（要在 `pitfalls.md` 里说明为什么改、按什么数改）；
   - **单独记一笔**：判据不动，在**本文件 §四** 这张表里加一行（写清出处、实测值、不是回归的证据）。
3. **谁拍板**：改规格属于「改契约」，要人拍板（`pitfalls.md` C2/C3 都留了「请你拍板」）；
   只记账的话，改这份文件就够了。
4. **禁止的修法**：为了让 #5 好看去缩字号、压行距、拆掉内容 —— 那是牺牲课堂上真正要看的东西
   （投影字号才是这条判据存在的理由）。

## 五、分级修正阶梯（`shell-boundary.md` §八 原话，照抄）

```
1–40px 微调 / 40–90px 局部压 / 90–160px 拆页 / 160px 以上才删内容
⛔ 修完复测，白空变大说明修过头
```

怎么用（`validate-deck.mjs` 会自动按超出量给你分档）：

| 超出量 | 动作 | 说明 |
|---|---|---|
| 1–40px | **微调** | 收 padding / margin / 行高的小数，或缩一档 `clamp()` 上限 |
| 40–90px | **局部压** | 压一个块的间距（例如页脚、`recap-strip`），不动字号 |
| 90–160px | **拆页** | 一页讲不完就分两页（外壳本来就支持分页 + 翻页同步） |
| 160px 以上 | **才删内容** | 前面三档都试过还超，才考虑去掉冗余块 |

**复测纪律**：
1. 一次只动一档，改完立刻 `node scripts/validate-deck.mjs <课时>`；
2. 三个数一起看：`bottom`（还溢出吗）、**自然高**（外壳还承载得住吗）、**白空**（改过头了吗）；
3. **白空变大 = 修过头**（内容被压扁/收窄，投影上反而更空更小）——看到这个信号就回退上一档；
4. 改完的产物要重新过一遍 `verify.py` 的 12 条（尤其第 12 条自然高度，确认没把版式改坏）。

```bash
cd ~/.agents/skills/kpf-speaking-deck

node scripts/validate-deck.mjs fce            # M1 溢出/白空 + M2 标题间距（+ 分级阶梯）
node scripts/validate-deck.mjs pet ket --raw  # 再带上写这份文档要用的原始值（缩放 / 字号 / 素材）
node scripts/validate-deck.mjs fce --m3       # M3 实测：调 scripts/safari-counts.py（需要真 Safari，先起服务+开窗）

python3 scripts/verify.py fce pet ket         # 12 条判据 + 第 12 条逐视图对照表（自起服务，无需先跑 serve-verify.sh）
bash scripts/serve-verify.sh                  # 只有 Safari 实时链路（safari-verify.sh / --m3）需要这三对服务（8894–8899）
```

> `validate-deck.mjs` 的 M3 一行**永远是委托**：headless 只有一个窗口、没有 peer，同步风暴（双窗口回环）
> 在那边根本不会发生 —— 所以它只打印委托命令，`--m3` 时才真的去调 Safari 那一路，**不伪造数字**。
